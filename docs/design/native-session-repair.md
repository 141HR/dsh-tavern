# 原生会话可修复：存档永不因原生会话而废

状态：第 1 步已实现（`tavern-plugin/lib/domain/native-surface-repair.js`，尚未接入任何操作），其余待实施。

## 问题

普通游玩有两份记录：

- **Tavern Chat（Story Timeline）**：楼层、变量、checkpoint、历史 revision。`CONTEXT.md` 定义它为唯一权威存档。
- **原生 DSH Session**：只追加的事件日志，`surface` 是当前模型上下文。`CONTEXT.md` 定义它为 Projection。

实际实现里，Projection 反过来卡住了权威：回退、重新生成、编辑正文、分叉、撤销回退都要先在原生 surface 里精确定位那一轮（anchor、tombstone、failed tail、`regeneratedDshTurns` 映射、迁移重编号、压缩边界……），定位不到就拒绝：

| 拒绝 | 位置 |
|---|---|
| 当前轮次已不在可回退的消息流中 | `domain/rollback-surface.js:584` |
| 旧正文已经不在当前模型消息面中 等 | `domain/rollback-surface.js:365,379,393,404` |
| 最后一轮正文已不在当前上下文中，无法编辑 / 模型上下文已变化 | `domain/body-editor.js:90,107,155` |
| 重新生成的原生历史边界不匹配 等 | `domain/regeneration-recovery.js:30,67,96,101` |
| 撤销回退时保存的上下文已不存在 | `domain/surface-restoration.js:21,23` |
| 该回合缺少已完成的原生上下文边界 | `domain/conversation-fork-point.js:46,49` |

只要出现一次对不上，后续所有修改历史的操作都被拒绝，玩家只能"继续发送新消息"，坏回复永远留在上下文里——存档实际报废。仓库里标题明确为回退相关的修复已有 47 个，每个都是补一种新的对不上，补不完。

## 不变式

> **存档只由 Chat 决定。原生 Session 出任何问题，代价最多是重算坏掉的那几轮，不能让任何操作被拒绝或让存档不可继续。**

推论：

1. 修改历史的操作只校验 Chat 自身（是否有可回退轮次、是否正在生成），不再以"原生 surface 能否定位"为前提。
2. Chat 先提交；原生同步在其后，失败只会把原生会话标记为待修复。
3. 原生会话随时可以由 Chat 修复：保留与 Chat 一致的最长前缀，只重写其后的尾部；修复是幂等、可中断重试的。

## 方案

### 1. 修复原语 `repairNativeSurface(session, chat)`：只修坏掉的尾部

**不整段重建。** 坏掉的几乎总是最后一两轮（回退、重新生成、编辑都只动尾部），前面的 surface 是好的，必须原样保留——它就是提示词缓存的前缀。玩到 1000 轮坏一轮，只修那一轮。

步骤：

1. **从末尾往前找最长一致前缀。** 对 Chat 的第 k 轮（k 从最后一轮往前），用楼层的 `nativeAnchor` 找到它在 surface 上的输入与正文节点，比对正文文本（楼层的 `text`，即发给模型的那份）。第一个"节点在、顺序对、文本一致"的轮次 k 就是断点：第 1..k 轮及其之间的一切（稳定前缀、变量目录、压缩摘要、已退役的空 frame、工具痕迹）都保留不动。
   - 只比对断点之后的少数几轮，成本与"坏了几轮"成正比，与总轮数无关。
   - 锚点失效（如存档迁移重编号）时，退化为在 surface 末尾按文本往前匹配。
   - 只看最后一次压缩之后的节点：被压缩掉的轮次以摘要为断点，摘要原样保留。压缩之后一轮都对不上时，保留摘要、重写最近 10 轮（压缩本身保留原文的轮数，`RETAINED_STORY_ROUNDS`）。
   - 最后一轮完好、但其后残留中断的输入/半截正文/工具结果时，只用一个空占位节点遮掉残留，最后一轮不动。注入的上下文（frame、变量变化）和空占位不算残留。
   - 开场白按其固定 id 识别，可作断点；连开场白都找不到才从稳定前缀之后整段重写——这是极端兜底，不是常态。
2. **只替换断点之后的节点。** 用一次 `replace` 把"第 k 轮正文之后的全部节点"替换为第 k+1 轮的第一条事件，其余 `append`（`domain/session-surface-mutations.js`）。事件日志仍只追加。
3. **不重写 frame。** 第 k+1..N 轮只写输入与正文。已生成正文的轮次不再需要它的 frame（现行 `retireForegroundFrames` 也会清空旧 frame）；下一轮的世界书快照、卡片系统提示更新按 surface 上现有内容计算增量（`domain/worldbook-snapshot.js`），被替换掉的快照会在下一轮自然重新注入。
4. 修复写入的节点自身也是锚点的根（`domain/round-anchor.js`）。调用方在同一 Chat 事务里刷新第 k+1..N 轮的 `nativeAnchor`，清除这些轮次相关的 `regeneratedDshTurns`、残留 `bodyEdit` 标记，使后续快速路径重新可用。

原地修复，**不新建 Session**：sessionId 是 chat 链接、模型请求日志、稳定前缀、资源工作区、插件和客户端路由的共同键（`domain/tavern-conversation-registry.js`、`domain/model-request-log.js` 等），换 Session 要迁移全部这些键。不写新的 `turn/start`/`turn/end`，原生轮次编号继续只增不减（`docs/plugin-api.md` 已说明可能不连续）。

**缓存影响**：断点之前字节不变，缓存照常命中；只有断点之后的少数几轮需要重新计费，和正常发新一轮的代价同一量级。压缩摘要在断点之前，一并保留。

### 2. 待修复标记与触发点

Chat 新增持久字段：

```js
chat.nativeSync = { status: 'stale', reason: '<哪个操作、为何失败>', revision: <Chat revision>, at: <ts> }
```

- **写入**：回退、重新生成、编辑正文、撤销回退在 Chat 提交后同步原生；快速路径抛错或定位不到时，不再向用户抛出，而是写入 `stale`。
- **执行**：以下时机发现 `stale` 就先修复，成功后清除标记：
  - 发送下一轮前台请求前；
  - 打开对话（会话恢复）时；
  - 重新生成开始前（需要干净上下文）。
- **崩溃安全**：标记在修复 flush 成功后才清除；中途崩溃下次再修复一次即可，修复只依赖 Chat，天然幂等。
- **一致性检查**：打开对话时比对 Chat 与 surface 的最后一轮（轮数、最后一条正文 hash）。不一致直接置 `stale`，不弹错。

### 3. 修改历史的操作改为"Chat 优先"

| 操作 | 现在 | 改为 |
|---|---|---|
| 回退本轮 | 先定位原生 target，找不到拒绝 | 只看 Chat 有无可回退轮次；Chat 截断提交后尝试快速路径，失败置 `stale` |
| 重新生成 | 先定位旧正文 | 同上；生成前若 `stale` 先修复，再发请求 |
| 编辑正文 | 定位最后一轮，找不到拒绝 | 直接提交 Chat；原生替换失败置 `stale` |
| 撤销回退 | 恢复保存的 surface 片段 | Chat 恢复到回退前 revision；原生恢复失败置 `stale` |
| 存档救援导入 | 标记为"不可回退/重新生成" | 取消此限制，修复即可 |

`rollbackAvailability` 的拒绝原因只剩"没有已提交轮次"与"正在生成/后台处理"。

### 4. 后台 Agent 与 MVU

- **后台会话：沿用同一个，不新建。** 前台修复不改 Chat，后台无需因此变动；后台跟随 Chat 回退靠的是它自己已有的原地回退（`domain/background-surface.js` 的 `rewindBackgroundSurface`：把 checkpoint 边界之后的任务历史在同一 Session 里替换掉）。边界找不到时按同一原则降级为 `rewindTo: -1`，即在**同一个后台 Session** 里清掉前缀之后的全部任务历史，下一次结算从 Chat 当前状态重新开始。现有"改用新的后台会话"（`background-agent-sessions.js:277-302`，#164）只在宿主不支持替换 surface 时触发；随包固定的 DSH 运行时（ADR 0007）支持替换，不会走到，本方案不新增任何新建后台会话的路径。
- **MVU 与变量**：变量和回执都在 Chat 楼层里，修复不触碰。进行中的 MVU 投递按现有规则校验 branch/revision，过期即作废。
- **模板展示、状态栏**：按 Chat 楼层渲染，不受影响。

### 5. 第二步（本次不做，确认后另行实施）

**恢复到第 N 轮**：Chat 已保留最近 50 轮的历史 revision（`domain/conversation-fork-point.js` 的 `conversationStateAtTurn`）。把该 revision 写回为当前 Chat 的新 revision，再置 `stale` 修复。连回退本身做错了也能撤回，是最后一道保险。

**删除补丁逻辑**：修复路径稳定后，评估删除 `rollback-surface.js` / `regeneration-recovery.js` 中只为"定位不到就拒绝"服务的分支，改为快速路径失败即修复。

## 代价与风险

- 修复的那几轮需要重新计费（通常只有最后一轮），与正常发新一轮相当；断点之前缓存照常命中，压缩摘要保留。
- 极端兜底（锚点和文本都匹配不上，只能从稳定前缀之后整段重建）才会整段缓存失效并丢失压缩摘要，需立即强制压缩一次（`domain/foreground-compaction.js`）。测试需证明常见故障都走不到这里。
- 重算的最后一轮 frame 按当前人物卡/世界书生成；若人物卡在此期间被改动，内容会与原轮不同（与"重新加载人物卡"语义一致，可接受）。
- 插件：修复后发一次 `timelineChanged`，插件按现有协议重读历史，无新事件类型。

## 验证

- 单元：故意破坏 surface（删 anchor、模拟迁移重编号、插入压缩检查点、插入孤立 tombstone），回退/重新生成/编辑均成功且 Chat 与修复 surface 一致。
- 单元：修复中途抛错 → 标记保留 → 再次触发后成功；修复两次结果相同。
- 单元：1000 轮存档损坏最后一轮，修复只替换最后一轮之后的节点，前 999 轮 surface 节点（含压缩摘要）逐个不变。
- 回归：现有 `tests/body-editor*.test.mjs`、回退/重新生成/撤销相关测试，快速路径行为不变。
- E2E：`tests/e2e` 新增 `--native-rebuild` 场景：游玩 3 轮 → 注入 surface 损坏 → 回退 → 重新生成 → 继续游玩，检查请求上下文与 Chat 一致。
